# タスク一覧：Code Defender

企画書 [game_plan.md](game_plan.md) をもとにした開発タスクです。企画書で「未定」「案」「叩き台」「ドラフト」となっている内容は、決めるタスクとして分けています。

## 0. 仕様を決めるタスク
- [x] X上での具体的な動かし方を決める（Webページとして作り、Player Cardのメタタグも付ける）
- [x] エンジニアの性格の種類を決める（几帳面、消極的、適当、サボりがち、真面目、冷静沈着、陽気、根暗）
- [x] パラメータを決める（疲労度・集中力・技術力・愛着心）
- [x] 性格ごとのパラメータの傾向を決める（3段階、game_plan.md参照）
- [ ] 性格ごとのパラメータの具体的な数値を試作で調整する
- [x] 疲労度・集中力・技術力の効果を確定する
- [x] 給料が愛着心に与える影響の詳細を決める（昇給は徐々に反応が薄く、減給は如実に低下）
- [ ] 給料と愛着心の計算式・係数を試作で調整する
- [x] 疲労度の仕組みを入れるかどうか決める（入れる）
- [x] 技術的負債の仕組みを決める（開発スピード低下・不具合率の増加・閾値超えの放置で大障害）
  - #150 で開発スピード低下（生成間隔の延長）は無効化（TECH_DEBT_SPAWN_INTERVAL_MAX_MULTIPLIER = 1）。負債で生産量（コード＋バグの総生成数）は落とさない。不具合率の増加と閾値超えの放置による大障害はそのまま
- [ ] 技術的負債の具体的な数値（溜まり方、閾値、放置時間、大障害の損害額）を決める
- [ ] 各ランクの不正コード率（開始時・上限）を確定する
- [ ] 給料、売上、損害額などの各種数値を決める
- [x] 支払い（給料）が発生する「一定期間」の長さを決める（1分＝ゲーム内1ヶ月ごと）
- [x] 不正なコードの種類を決める（脆弱性4段階、スパゲティコード、バグ、コード重複、低パフォーマンス、タイポ）
- [ ] 不正なコードの種類ごとの見た目・強さ・損害額を決める
- [x] 採用するアイテムと、各アイテムの役割・効果を確定する（game_plan.mdのアイテム一覧）
- [x] アイテムの価格帯と支払いターム（1回払い・月額払い）を決める
- [ ] アイテムの範囲・攻撃力・価格の具体的な数値を試作で調整する

## 1. 開発環境
- [x] Vite＋TypeScriptのプロジェクトを作る
- [x] Phaserを導入する
- [x] 開発サーバーで空の画面が表示されることを確認する

## 2. フィールドとルート
- [x] 2Dフィールドを表示する
- [x] リリース地点を配置する
- [x] エンジニアごとの出現場所からリリース地点までの決まったルートを作る
- [x] エンジニアが増えたときに出現場所とルートを追加できるようにする
- [x] ルートを曲がりくねったランダムな形にする

## 3. 主人公
- [x] 主人公（エンジニア）を表示する
- [x] 主人公がフィールドを自由に動き回れるようにする
- [x] 主人公がコードを攻撃できるようにする

## 4. コード
- [ ] 正常なコードと不正なコードを、色や形で見分けられる見た目で作る
- [ ] 不正なコードの種類（脆弱性4段階、スパゲティコード、バグ、コード重複、低パフォーマンス、タイポ）を実装する
- [x] コードが出現場所からルートに沿ってリリース地点へ流れるようにする
- [x] エンジニアのランクに応じた割合で不正なコードを出す
- [x] 不正なコードの割合を可変にする
  - 補正は effectiveMaliciousRate に渡す差分（パーセントポイント）で行う。補正後の下限は CODE_MALICIOUS_RATE_MIN
- [x] 時間とともにコードの流れを速くし、不正なコードを増やす
  - 不正コード率はゲーム内10日（MALICIOUS_RATE_STEP_MS）ごとに 3 ポイント（CODE_MALICIOUS_RATE_INCREMENT）上がる(#150)。コード速度の間隔（DIFFICULTY_STEP_MS）とは別

## 5. 判定とお金
- [x] 不正なコードを倒せるようにする
- [x] 正常なコードを攻撃したら減点する
- [x] 正常なコードがリリースされたら売上として加算する
- [x] 不正なコードがリリースされたら障害を起こし、損害として資金を減らす
- [x] 不正なコードは攻撃で弱くなり、HP が尽きると正常なコードに変わる(#173)
  - リリース時の損害 = 種別の損害 × (残り HP ÷ 初期 HP)（0〜1 に収め、円単位で丸める。incident.ts の scaledIncidentDamage）。残り HP はリリースのペイロードの remainingHp で渡す。書き置きで防いだ障害の損害額も同じ値
  - HP が 0 以下になったコードは消さず、同じ id・位置の正常なコードに描き直す（codeFlow.ts の toNormalCode）。撃破の演出と code-defeated はそのまま出す
  - 直ったコードは正常なコードとして扱う（アイテムの攻撃対象外・主人公が攻撃すると減点・テストツールの足止めなし・リリースで売上と技術的負債の精算）
  - CI の阻止・猫・退職で消える挙動と予約した障害は変えない。弱っていく途中の見た目は変えない
- [x] 1分（ゲーム内1ヶ月）ごとにエンジニアの給料を引く
- [x] ゲーム内の経過日数を表示する
- [x] 資金がなくなったら倒産でゲームオーバーにする
- [x] スコアとして倒産までの累計売上を表示する

## 6. エンジニアの雇用
- [x] ジュニア・ミドル・シニアの3ランクから雇えるようにする
- [x] ランクごとに不正コードの割合を変える
- [x] ランクごとに給料を変える
- [x] 雇ったときに性格がランダムで付くようにする
- [x] 雇うと出現場所とルートが増えるようにする
- [x] エンジニアごとに疲労度・集中力・技術力・愛着心のパラメータを持たせる
- [x] 性格ごとにパラメータの値を変える
- [x] 休暇で愛着心が上がり、疲労度が高いまま働かせると下がるようにする
- [x] 給料が愛着心に影響するようにする
- [x] 愛着心が最低になったら自主退職し、そのルートが消えるようにする
- [x] 給料の初期額をランクで決める
- [x] プレイヤーがいつでも昇給・減給できるようにする

## 7. 休暇
- [x] 好きなタイミングでエンジニアに休暇を与えられるようにする
- [x] 休暇中はそのエンジニアのコードを新しく生成しない
  - 止めるのは新規生成だけ。休暇前に生成済みのコードとバグは流れ続け、通常どおりリリース・撃破・迎撃される(#163)。コードフリーズ中は従来どおり移動も止まる
- [x] 休暇中も給料を引く
- [x] 休暇を取らせること自体ではポイントが増減しないようにする
- [x] 休暇を与えると不正コード率が下がるようにする
- [x] 休暇の操作方法と効果の案内文を HUD に常時表示する(#150)
  - #156 で常時表示をやめ、出現地点を押すと開くエンジニアのポップオーバーの中に出す。休暇の切り替えとAIエージェントの購入もポップオーバーのボタンで行う（出現地点を押しても休暇は直接切り替えない）

## 8. 機能開発とリファクタリング
- [x] 機能開発とリファクタリングの割合を指定できるUIを作る
- [x] リファクタリングを強化すると品質が良くなる（不正コードが減る）ようにする
  - 補正は effectiveMaliciousRate に渡す差分 −k × 割合（k は REFACTORING_MALICIOUS_RATE_REDUCTION_MAX）。補正後の下限は CODE_MALICIOUS_RATE_MIN
- [x] 機能開発を強化すると売上に繋がるようにする
- [x] 技術的負債を溜める・返す仕組みを入れる
- [x] 技術的負債に応じて開発スピードを下げる
  - #150 で倍率を 1 にして無効化（仕組みは残す）。負債で生産量は落とさない。不具合率の増加と大障害はそのまま
- [x] 技術的負債に応じて不具合率を徐々に上げる
- [x] 技術的負債が一定量を超えて放置されたら大障害を起こす

## 9. アイテム
- [x] ステージポイントによる初期配置の画面を作る
  - #157 でマウス操作にする。購入バーでアイテム、パネルのボタンでエンジニアを選び、次に置く場所をクリックする（最初は未選択。キーボード操作の説明は出さない）
  - #156 で初期配置のパネルを左上に移す。置くアイテムは右上のアイテムのアイコンで開くメニューから選ぶ（初期配置の間はエンジニア・開発バランスのアイコンは薄く表示して開かない）
  - エンジニアの出現場所も選べる。置けるのは出現列（ENGINEER_SPAWN_COL）の空いた行で、setup の間だけ床の色を変える。ルートは自動で作り、置いたアイテムに重なれば作り直す（INITIAL_PLACEMENT_ENGINEER_ROUTE_ATTEMPTS 回まで）
  - 置いたアイテムとエンジニアは右上の×で取り消す（アイテムはポイントを全額返す）。エンジニアを全員置くまで開始できない
- [x] リリースで稼いだポイントでプレイ中にアイテムを追加できるようにする
- [x] アイテムが正常なコードを攻撃しないようにする（猫は例外）
- [x] アイテムごとに得意な不正コード・範囲・攻撃力を持たせる
- [x] 月額払いのアイテムは1分ごとに費用を引く
- [x] CodeRabbitを実装する
- [x] AIコーディングエージェント（強い・普通・安い）を実装する
- [x] テストツールを実装する
- [x] CIを実装する
- [x] セキュリティスキャナー（脆弱性クリティカルに有効なダメージ）を実装する
- [x] 猫を実装する
- [x] その他のアイテム一覧のアイテムを実装する
  - アイテムの四角の大きさを配置グリッド（16px）1マスに合わせた(#154)。辺・角が接するだけなら隣のマスにも置ける。文字は 8px・黒縁と四角の縁取りは 1px
- [x] レベルでアイテムを解放し、アイテムの価格を半額にする(#164)
  - ゲーム内30日ごとにレベルを1上げる（経過時間から求める。上限なし）。左上の経過日数を「Lv.2 / 30日」の形にする（初期配置の間は「Lv.1 / 0日」）
  - Lv.1 は CodeRabbit・Linter・テストツールの3種類、Lv.2 で CI、以降は ITEM_TYPES の順に1レベル1種類ずつ増え、Lv.16 で18種類すべてになる（ITEM_REQUIRED_LEVEL_BY_TYPE）
  - アイテムのメニューとキー 4〜9 は解放済みのアイテムだけを並べる。レベルが上がるとメニューを描き直し（通知は出さない）、ページはそのまま残す。リスタートで Lv.1 に戻る
  - 購入・初期配置でも解放前のアイテムは「まだ使えないアイテムです」で断る（資金・ポイント・配置は変えない）
  - アイテムの価格を半額（安い 12,500・普通 25,000・高い 50,000円）にする。月額払いの月額も半額になる。AIエージェントの価格は AI_AGENT_PRICE_TIERS で半額前のまま
- [x] 見た目では空いている場所にアイテムを置けるようにする(#162)
  - 判定の大きさ（16px）は見た目と同じだった。置けない範囲が描いている物より広かったので、描いている物に合わせた
  - ルートの置けない帯は、描いているルートの外形（下地線の太さ 12px の半分 = 中心線から 6px。折れ点・端点の丸も半径 6px、矢印は 5px で内側）にする。外形に接するだけなら置ける（以前は 8px で 2px 広かった）
  - 初期配置の間に置けない範囲は、外接矩形1つをやめ、パネル・エンジニアの選択ボタン・開始ボタン・メッセージの4つの矩形にする（開始ボタンの右など、矩形の間は置ける）
  - 置けるかどうかを示す枠（16px）を出す。初期配置ではポインターの下のセル（ボタンなどの上・フィールドの外・アイテム以外を選んでいるときは出さない）、プレイ中は主人公が置くセルに出す。緑なら置ける、赤なら置けない
  - 枠の可否はクリック・購入と同じ判定から決める（初期配置は placeInitialItem、プレイ中は既定の置けない範囲での isPlaceableCell）
  - 出現場所（半径 19.5px）・リリース地点（パルスの最大半径 28px）・「リリース」のラベルの置けない範囲は描いている物と同じなので変えない

## 10. UI
- [x] 資金・累計売上を常に表示する
- [x] ゲームオーバー画面でスコアを表示する
- [x] 画面の情報を減らす(#156)
  - 常時表示は左上の経過日数・右上の3つのアイコン（エンジニア・アイテム・開発バランス）・右下の小さな指標だけにする。左の HUD と下端の購入バーは撤去
  - アイコンを押すとその下に選択肢を縦に並べたメニューを開く（一度に1つ。同じアイコンで閉じ、外を押すと閉じる）。エンジニアは雇用・選択・昇給減給、アイテムは購入（6枠とページ）、開発バランスは割合の11段階
  - 右下に資金・累計売上・月末に支払うお金（給料＋月額アイテム＋AIエージェントの月額）と、技術的負債の段階（緑: 正常 0〜30、オレンジ: 注意 31〜60、赤: 要解消 61〜100）を出す
  - キー操作は残すが、画面にはキー名を出さない
- [x] 英語に対応し、文言を言語ごとの別ファイル（src/i18n/locales/）にする(#158)
  - 表示言語は URL の `?locale=` → ブラウザーの言語設定 → 既定の日本語の順に決める（起動時に1回。リスタート後も同じ言語）
  - 言語カタログは TypeScript（日本語の形を Messages 型にし、英語のキーの過不足は型検査で防ぐ）。言語を足すときはカタログを足し、SUPPORTED_LOCALES に加える
  - 常時表示・メニュー・ポップオーバー・初期配置・通知・ゲームオーバー画面の文言をすべてカタログから読む。レイアウトの値（位置・大きさ）は言語で変えない
  - リリース地点のラベルの置けない矩形は、表示中の言語のラベルの推定幅（textMetrics.ts）から求める
- [x] 情報をコンパクトにする(#165)
  - 左上は「Lv.2 📅30」にする（経過日数の語をやめ、言語によらず同じ形）
  - 右下の指標は語をやめ、絵文字と数字を2列 × 2行に並べる（💰 資金・💸 月末に支払うお金（赤文字）・📈 累計売上・技術的負債は 🔵 正常 0〜30 / 🟡 注意 31〜60 / 🔴 要解消 61〜100 と数字）。絵文字は config.ts の HUD_ICONS・TECH_DEBT_LEVELS
  - 常時の説明（初期配置パネルの操作説明の行・ポップオーバーの休暇の案内文）をやめ、右上の一番右の ℹ️ で開くゲームの説明に移す。説明の数値は config.ts の値から作る（help.ts）
  - ゲームの説明は全面の半透明の背景で下の操作をすべて止め、開いている間は時間も止める。背景か ✕ で閉じる（押したままのポインターでは動かない）。初期配置の間とプレイ中は開け、ゲームオーバー中は開かない
  - キーボードの操作（移動・攻撃・雇用・選択・昇給減給・AIエージェント・アイテム・ページ・割合・開始・リスタート）をすべてやめ、マウス（タッチ）だけにする。ゲームオーバー画面の案内からも Enter を消す
  - 開発バランスのメニューは11段階の選択肢をやめ、2色のゲージ（左が機能開発・右がリファクタリング）と割合の文言、◀ / ▶ のボタン（1段階 10%）にする
